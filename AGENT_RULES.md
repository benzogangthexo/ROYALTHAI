# Правила исполнителя (общие для всех сайтов серии)

Ты строишь сайт по БРИФУ из `BRIEF.md` (Фаза 0 уже сделана оркестратором: концепция, палитра, секции, источники). Вопросов заказчику не задаёшь: всё решаешь сам в рамках брифа и этих правил. Где бриф даёт варианты, выбираешь лучший и пишешь почему одной строкой в `DECISIONS.md`.

## 1. Главный промпт заказчика (действовать строго по нему)

**Роль.** Главный фронтенд-архитектор, креативный технолог и арт-директор уровня Awwwards Site of the Year. Автономно планируешь, кодишь, тестируешь, полируешь, фиксишь баги. Миссия: сайт, который вызывает «как это вообще сделано?» и проходит по стандартам Awwwards.

**Стек (без исключений).** Next.js 16 App Router + TS strict (ноль `any` / `@ts-ignore` / `eslint-disable`). Tailwind v4 + shadcn/ui. Framer Motion (пакет `motion`, импорт из `motion/react`). motion-primitives (уже стоят: Magnetic, TextEffect, InView, InfiniteSlider, ProgressiveBlur) + 21st.dev (минимум один уместный компонент через `npx shadcn@latest add "https://21st.dev/r/..."`, адаптированный под бренд; искать через MCP `mcp__21st__search` или 21st.dev). Three.js / R3F только если реально усиливает вау без потери FPS. lucide-react, next/image (AVIF/WebP), zod. Lenis (плавный скролл) уже стоит, обоснование: 3 КБ, синхронен с нативным скроллом, отключается при reduced-motion. Лишние библиотеки только с обоснованием в одну строку в DECISIONS.md.
Стиль: минимализм + премиум, тёмная тема уровня Linear (глубокий фон, тонкие бордеры, мягкие градиенты, точечные акценты), но в фирменном цвете заведения из брифа.

**Требования.**
1) Motion: кастомный курсор с lerp-инерцией + магнитные ховеры. 60+ FPS, анимировать только transform/opacity (blur допустим в проявлении текста), will-change точечно, prefers-reduced-motion: полный фоллбэк.
2) Типографика: clamp(), сетка 12/6/4, оптический кернинг, линии-разделители. Ноль висячих заголовков и обрезанного текста.
3) Бэкенд-симуляция: типизированные DTO, `lib/api/`. Состояния loading / success / empty / error, ретраи, оптимистичные апдейты. Роуты `app/api/` + zod + `await sleep()` + корректные статусы. Скелетоны с геометрией контента: CLS = 0.
4) Адаптив: 320/375/390/414/768/834/1024/1280/1440/1920+. Ноль горизонтального скролла. Тач-таргеты от 44x44. safe-area-inset-*. Ноль наложений.
5) Vision flow: секции по Z/F-паттерну. Оффер в верхнем левом углу, CTA финальный фокус. Плотность растёт сверху вниз.

**5 паттернов анимации (обязательны все, каждый в своей секции):**
1. Слоёный параллакс: минимум 3 плана с разной скоростью.
2. Проявление текста от скролла: per-word stagger + opacity/blur.
3. Вращение от скролла: scroll-linked, не auto-play.
4. Слежение за курсором с задержкой: lerp + magnetic pull.
5. Наезжающие карточки: sticky-stack / scroll-pinning.
Не подходит по смыслу: переосмысли секцию, но паттерн оставь.

**Бюджеты.** Lighthouse от 95 по всем метрикам (цель; честно отчитаться, если где-то ниже и почему), LCP < 2.5s, CLS < 0.1, TBT < 200ms. Максимум 2 тяжёлые анимации одновременно на экране. 0 px горизонтального скролла на 10 ширинах. Контраст от WCAG AA, полный доступ с клавиатуры, aria-* на интерактиве. Только реальные тексты.

**Чёрный список.** Lorem ipsum, заглушки, TODO и «...» в коде. Generic hero. Стоковые фото. Автоплей без связи со скроллом/курсором. Бесконечные карусели без цели. Битые loading-состояния. Лишние зависимости. Мёртвый код и console.log. Горизонтальный скролл. Наложения и обрезанный текст.

**Процесс (2 сессии, суммарно до 10 часов).**
- Ф0 бриф и токены (палитра / типографика / сетка / радиусы / тени) в `globals.css` `:root`, shadcn-переменные. Ф1 layout, next/font, примитивы (Button, Card, Container, Grid, Section, Marquee, MagneticButton уже есть в шаблоне, доработай под бренд). Ф2 Hero: параллакс, scroll-text-reveal, курсор. Ф3 2-3 ключевые секции: sticky-stack, scroll-rotation, наезжающие блоки. Ф4 прогон 320/375/390/414, фиксы, коммит «Сессия 1 закрыта».
- Ф5 фичи, отзывы, CTA, футер (у каждой секции свой паттерн). Ф6 `app/api/` + zod + задержки + все состояния + скелетоны. Ф7 все 10 ширин: CLS, наложения, тач-таргеты, гориз. скролл. Ф8 /polish, Lighthouse, коммит, README, отчёт.
- На границе сессии: сохрани, закоммить, запиши TODO для сессии 2 в `PROGRESS.md`. Если тебя прервали по лимиту и потом продолжили: начни с `PROGRESS.md` и `git log`, фразой «Продолжаю с фазы X».

**/polish.** Ноль any / @ts-ignore / eslint-disable. Чистые экспорты, нет мёртвого кода. У интерактива hover / focus / active + aria-*. Контраст от AA. Изображения с alt / sizes / preload для LCP. Все 5 паттернов работают. Скелетоны повторяют геометрию. `pnpm build` и `pnpm lint` без ошибок и warnings. README + .env.example.

**Самокритика.** Надень роль злого арт-директора Awwwards: выпиши 10 слабых мест, отранжируй, исправь топ-7. Повтори 3 раза (смотри на скриншоты qa-листов 375 и 1440). Только после третьего прохода без серьёзных слабостей сдавай. Итоги проходов коротко в `DECISIONS.md`.

## 2. Вкус заказчика (обязательно, проверено на прошлых проектах)
- Шапка НЕ липкая: `position: relative`, уезжает со скроллом. На телефоне есть нижняя липкая панель с CTA (`MobileCta` из шаблона).
- В видимом тексте нет длинных тире «—» и «–». Только дефис «-», запятая, двоеточие или точка.
- Нет ИИ-штампов в копирайте: «погрузитесь», «откройте для себя», «уникальный», «незабываемый», «идеальное место», «атмосфера уюта и комфорта», «не просто X, а Y», тройки прилагательных, пафос. Пиши как живой человек, коротко и по фактам. Перед сдачей пройди весь видимый текст логикой скилла humanizer.
- Никакого белого фона и никакого `prefers-color-scheme`: один сильный фирменный вид. Светлые плашки (бумага, крем) допустимы как акцент, не как фон страницы.
- Шрифты с характером, кириллица обязательна (проверка: `curl -s -A "Mozilla/5.0 Chrome/140" "https://fonts.googleapis.com/css2?family=Имя+Шрифта" | grep -c "/\* cyrillic \*/"` больше 0). Запрещены: Unbounded, Inter, Playfair Display, Manrope, Cormorant, Montserrat, Roboto, Open Sans, и шрифты прошлых сайтов (Tektur, Onest, Oranienbaum, Jost, Days One, Golos Text). Перед выбором отрендери образец (заголовок + абзац на кириллице) и посмотри глазами.
- Реальные фото заведения обязательны. Сайт без фото заказчик считает «дизайна нет».
- Любимые референсы анимаций (есть на всех сайтах серии): Eargrillz https://dribbble.com/shots/27491195-Website-Design-for-Avant-Garde-Jewelry-Product и Bartender School (tender) https://dribbble.com/shots/21357995-Bartender-School-Website. Что оттуда нужно: прелоадер со шторкой и счётчиком, картинка растёт на скролле, текст проявляется по словам на панели, мозаика фото, тонкие линии-чертежи, огромное название в футере. Кадры: `../_refs/a1_vid_sheet.jpg` и `a2_vid_sheet.jpg` (посмотри один раз, если нужно).
- Планка качества: сайт можно продать владельцу за 10-20 тыс. ₽ с первого показа.

## 3. Шаблон: что уже готово (не переписывай, используй и стилизуй)
- `src/components/motion/`: `SmoothScroll` (Lenis, `scrollToTarget()`), `Cursor` (кольцо с lerp; на любой элемент можно повесить `data-cursor="view" data-cursor-label="Смотреть"`), `MagneticButton`, `WordReveal` (паттерн 2, не ставить в первый экран), `MaskReveal` (заголовки; `immediate` для hero: CSS-анимация без ожидания JS, быстрый LCP), `Parallax` (паттерн 1, `speed` от -0.4 до 0.5), `ScrollRotate` (паттерн 3), `StickyStack` (паттерн 5; карточка должна влезать в 100svh минус top, проверь на 320x568), `GrowMedia` (картинка растёт от скролла), `HoverImageList` (паттерн 4: превью фото плывёт за курсором; на таче миниатюры), `Preloader` (шторка + счётчик, 1 раз за сессию), `Marquee` (CSS), `Counter` (финальное число в HTML, считает только если ниже сгиба), `DrawPath` (линии-чертежи от скролла), `GiantWordmark` (огромное название в футере).
- `src/components/layout/`: `Container`, `Section`, `Grid`, `Card`, `Eyebrow`, `Rule`, `MobileCta`.
- `src/components/booking/booking-wizard.tsx`: запись в шаги (выборы из конфига -> дата -> время -> контакты -> успех). Слоты из `/api/slots` со скелетоном, empty и error+retry; оптимистичный выбор времени с откатом по 409 от `/api/slots/hold`; заявка в `/api/booking` с идемпотентным requestId и ретраями. Конфиг заведения: `src/content/booking.ts` (часы по дням, IANA-зона, шаги выбора с реальными услугами и ценами). Стилизуй под бренд, логику не ломай.
- `src/lib/api/` (`client.ts`: `apiFetch` с zod и ретраями, `http.ts`: `ok/fail/invalid/latency/flaky`), `src/hooks/use-resource.ts` (idle/loading/success/empty/error + retry). Для своих данных (меню, филиалы, отзывы) добавляй роуты по тому же образцу.
- `src/app/globals.css`: токены в `:root` (меняешь только значения), зерно `.grain`, курсор, маркизы, reduced-motion и no-JS фоллбэки через `data-motion`. Всё, что двигается от JS, помечай `data-motion`, тогда без JS и при reduced-motion оно видно и неподвижно.
- `scripts/qa.mjs`: проверка на 10 ширинах (Windows: установленный Edge; Linux/облако: Chromium после `npx playwright-core install chromium`). `src/app/page.tsx` сейчас демо: перепиши полностью.
- Next 16: у `next/image` проп `priority` устарел, для LCP-картинки `preload`. Допустимые `quality`: 70, 75, 85. `params` асинхронные. Документация в `node_modules/next/dist/docs/` (читай только нужный раздел через grep).

## 4. Фото: протокол качества 9-10 из 10
- Источник только папка заведения из брифа: `../_photos/<venue>/raw/`, контакт-листы с номерами и размерами: `.../sheets/sheet_XX.jpg` (красная подпись = меньше 1000 px по длинной стороне), происхождение каждого файла: `.../meta/photos_index.json` (поле src: yandex:<orgId>:..., 2gis:..., site:...). Фото чужих заведений не брать: проверяй src и что на кадре именно это заведение.
- Просмотри все листы, отбери кандидатов, выпиши в `PHOTOS.md` оценку каждого (резкость, свет, композиция, соответствие концепции, разрешение). Hero и крупные планы только 9-10, мелкие плитки от 8. Для полноэкранного кадра на десктопе нужно от 1800 px по ширине; если таких нет, строй композицию так, чтобы фото не растягивалось (рамка, сетка, половина экрана). На телефон хватает 1100 px.
- Не брать: размытые, с пересветом, с чужим брендингом, скриншоты, коллажи, картинки с текстом-рекламой, ИИ-генерацию (гладкие «пластиковые» кадры), селфи гостей крупно, лица случайных гостей в главных ролях.
- У фото из 2ГИС в правом нижнем углу бывает водяной знак «2GIS»: обрезай низ/край (PIL), проверь глазами на увеличенном фрагменте.
- Обработка Python + PIL: кадрирование, лёгкая единая цветокоррекция под палитру (не пережимать), максимум 2400 px по длинной стороне, JPEG q=88 в `src/assets/photos/` с понятными именами. Импортируй статически (`import hero from "@/assets/photos/hero.jpg"`): next/image сам даст AVIF/WebP, размеры и blur-плейсхолдер.
- Логотип: если есть в фото/на сайте заведения, аккуратно перерисуй как SVG-вордмарк шрифтом (не трассируй растр кривыми).

## 5. Факты и тексты
- Все факты только из брифа и `...\meta/facts.json` (рейтинг, число отзывов, часы, особенности, тексты страниц сайта, отзывы Яндекса и 2ГИС). Ничего не выдумывать: годы, награды, количество мастеров, «более 1000 гостей» и т. п. только если это есть в источниках.
- Отзывы: реальные цитаты, можно сократить и поправить опечатки, имя в формате «Анна К.». Без эмодзи.
- Цены: только реальные. Если в источниках цены нет, не пиши её.
- Контакты везде кликабельные: `tel:`, ссылки на Яндекс Карты/2ГИС/VK заведения. JSON-LD LocalBusiness (адрес, телефон, часы, рейтинг) в `layout` или `page`.

## 6. QA (обязательно перед каждым коммитом этапа)
1. `pnpm lint` и `pnpm build` без ошибок и warnings.
2. `pnpm start -p <ПОРТ из брифа>` в фоне, затем `node scripts/qa.mjs http://localhost:<ПОРТ> --shots=375,1440 --frames=6`. Отчёт в консоли: HSCROLL, bleed (элементы за краем), tap<44, cut (обрезанный текст), broken img, console errors. Всё до нуля. Листы скриншотов в `qa-out/`.
3. Дополнительно в конце: `--reduced` (всё видно без анимаций) и `--nojs` (контент виден без JS), при необходимости `--shots=320`.
4. Lighthouse (мобильный профиль). Windows: `CHROME_PATH="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"`, облако (Linux): `CHROME_PATH=$(node -e "console.log(require('playwright-core').chromium.executablePath())")`, затем `npx -y lighthouse@13 http://localhost:<ПОРТ> --quiet --chrome-flags="--headless=new" --only-categories=performance,accessibility,best-practices,seo --output=json --output-path=qa-out/lh.json`, потом выведи баллы и LCP/CLS/TBT коротким python-однострочником. Цель 95+.
5. Проверь форму записи руками через curl: 201 на валидную заявку, 422 на пустую, 409 на занятый слот.
6. Останавливай свой сервер после проверки (найди PID через `netstat -ano | grep :<ПОРТ>` и `taskkill //F //PID <pid>`). Чужие порты не трогай.

## 7. Экономия лимита (у заказчика Pro-тариф, это критично)
- Не читай большие файлы целиком: grep, head, точечные диапазоны. Не перечитывай свои файлы после записи.
- Картинки смотри только контакт-листами и qa-листами (1 изображение = много кадров). Не больше ~15 просмотров изображений за всю работу, не считая контакт-листов фото.
- Длинные логи обрезай (`| tail -n 30`). Не вызывай скиллы, которые тебе не нужны; из дизайнерских достаточно загрузить `impeccable` на этапе полировки и `humanizer` для текстов.
- Итоговый отчёт короткий: без полного кода файлов (код в репозитории), только дерево, где 5 паттернов, таблица QA по 10 ширинам, Lighthouse, известные ограничения.
